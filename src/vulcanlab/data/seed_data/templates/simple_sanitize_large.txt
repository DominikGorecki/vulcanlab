You are an expert document structure sanitizer for a Retrieval-Augmented Generation system.

You will receive a condensed representation of a large Markdown document. It contains heading lines with original line numbers and short context snippets. Your job is to output heading-level modifications that produce a clean, semantically correct hierarchy for chunking and retrieval.

-----
Input condensed document >>>>

{condensed_document}

<<<< END OF INPUT
-----

Your task:
For every heading entry in the condensed document, decide one action and whether the section should be indexed.

Primary objective:
Ensure the final heading hierarchy is coherent and correct.

* Exactly one global document title should be H1 if a real title exists.
* No skipped levels anywhere. A child must be exactly one level deeper than its parent.
* Siblings must share the same heading level.
* No orphan subsections. If a heading implies it is a subsection but no valid parent exists above it, promote it to the nearest valid level.
* Remove false headings such as navigation, page markers, and boilerplate.

You must not reorder headings. Only decide keep, change, or remove for each heading line.

---

Heading validity rules

A heading is NOT a real heading if it is any of the following:

* Page numbers or navigation markers such as Page 3, p. 12, 12, 12 of 300
* Running headers or footers, repeated document title lines, repeated chapter titles
* Table of Contents, Contents, Outline, List of Figures, List of Tables, Index
* References, Bibliography, Works Cited, Footnotes, Endnotes
* Acknowledgments, Dedication, About the Author
* Copyright, Permissions, ISBN, publisher boilerplate
* Download metadata, scan metadata, URLs, repository notes, conversion tool stamps
* Dot leader navigation lines such as Title ..... 23
* OCR noise or character soup

If the heading is not real:

* action must be "remove"
* vectorize must be false
* do not include "new"

If the heading is real:
Choose "keep" only if both the heading level and heading text are already correct.
Choose "change" if you must fix hierarchy or text, including:

* Wrong level for the implied structure
* Sibling level inconsistency
* Level skip relative to surrounding structure
* Text cleanup needed: extra whitespace, broken glyphs, OCR artifacts, redundant running header prefixes, obvious truncation that can be safely corrected from context

When action is "change", "new" must be the full corrected Markdown heading line, including the correct number of # markers and cleaned title text.

---

Hierarchy rules for level changes

Infer structure using:

* Numbering patterns such as 1, 1.1, 1.1.1, Chapter 3, Part II, Appendix A
* Standard academic organization such as Introduction, Methods, Results, Discussion, Conclusion
* The surrounding context snippets

Constraints you must enforce:

* Do not skip levels.
* Parent and child differ by exactly one level.
* Siblings share the same level.
* Preserve existing numbering if present. Do not renumber and do not invent missing numbers.

Title rule:

* If a clear global title exists, it should be the only H1.
* If multiple title candidates exist, keep only the most global as H1 and demote others to appropriate levels or remove them if they are boilerplate.

---

Vectorize rules

vectorize should be true only when the section content is worth indexing for retrieval.

Set vectorize true for:

* Core topical content: definitions, explanations, arguments, examples, methods, results, discussion, conclusions, substantive appendices
* Substantive figure or table captions and analyses
* Glossary-like sections only if they contain real definitions useful for retrieval

Set vectorize false for:

* Navigation and tables of contents
* Reference lists and bibliographies
* Index material
* Acknowledgments, dedications, author bio
* Copyright and publisher boilerplate
* Download metadata, scan metadata, URLs
* Purely administrative or non-topical material

If action is "remove", vectorize must be false.

---

Output requirements

Respond ONLY with valid JSON matching this exact schema:
{{
"modifications": [
{{"line": 5, "action": "remove", "vectorize": false}},
{{"line": 12, "action": "change", "new": "## Methods", "vectorize": true}},
{{"line": 25, "action": "keep", "vectorize": true}}
]
}}

Rules for the output:

* Include one modification object for every heading entry shown in the condensed document, in the same order.
* "line" must match the line number from the condensed document.
* "action" must be exactly one of: "keep", "change", "remove".
* "vectorize" must be a boolean: true or false.
* "new" is required only when action is "change", and must be omitted for "keep" and "remove".
* Return ONLY the JSON object. No additional text.
